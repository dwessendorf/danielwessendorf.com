# Hosting danielwessendorf.com on the Future Learning Lab Hetzner server

Status: **proposal, not active.** The live site is still deployed by `.github/workflows/pages.yaml`.

## Approach

The site is plain static HTML generated by Hugo, so it needs no runtime on the server:

```
GitHub Actions (build with Hugo)
   └─ rsync over SSH, restricted key (rrsync) ──►  Hetzner server: /srv/www/danielwessendorf.com
                                                     └─ served by the reverse proxy that already runs
                                                        there (Caddy example below), automatic TLS
Cloudflare (optional, like futurelearninglab.de) ──► DNS + CDN in front of the server
```

- **No extra container, process or port.** The existing reverse proxy serves one more directory. Disk use is about 40 MB.
- **Build stays in CI.** The server never runs Hugo, Go or Node. Nothing to patch on the box.
- **Least privilege.** The deploy key can only rsync into the site directory. It cannot open a shell.
- **Near-atomic updates.** `--delay-updates --delete-after` swaps files at the end of the transfer, so visitors never see a half-uploaded site.
- **Hosted in Germany.** No US hosting provider in the request path (GitHub Pages and Netlify are US companies). This fits a privacy-first company story.

## One-time server setup

```bash
# 1. Site directory and a deploy user without a password
sudo mkdir -p /srv/www/danielwessendorf.com
sudo adduser --system --group --shell /bin/sh --home /srv/www/danielwessendorf.com deploy-dw
sudo chown -R deploy-dw:deploy-dw /srv/www/danielwessendorf.com
sudo chmod 755 /srv/www/danielwessendorf.com

# 2. rrsync ships with rsync >= 3.2.4 (Debian 12 / Ubuntu 22.04+). Older systems: /usr/share/doc/rsync/scripts/rrsync
sudo apt-get install -y rsync

# 3. Generate a key pair for GitHub Actions (on your laptop, not on the server)
ssh-keygen -t ed25519 -N "" -C "github-actions danielwessendorf.com" -f dw-deploy

# 4. Allow that key to rsync into the site directory and nothing else
sudo install -d -m 700 -o deploy-dw -g deploy-dw /srv/www/danielwessendorf.com/.ssh
echo 'command="/usr/bin/rrsync /srv/www/danielwessendorf.com/public",restrict ssh-ed25519 AAAA... github-actions danielwessendorf.com' \
  | sudo tee /srv/www/danielwessendorf.com/.ssh/authorized_keys
sudo mkdir -p /srv/www/danielwessendorf.com/public
sudo chown -R deploy-dw:deploy-dw /srv/www/danielwessendorf.com
```

The web root is `/srv/www/danielwessendorf.com/public`, so the `.ssh` directory is never served.

## Reverse proxy

If the server runs Caddy, add [`Caddyfile`](Caddyfile) to the configuration and reload Caddy. For nginx or Traefik the same rules apply: serve `/srv/www/danielwessendorf.com/public` as static files, use `404.html` for missing pages, and cache `/css`, `/js` and `/fonts` for a long time (Hugo fingerprints CSS and JS in production builds).

## GitHub repository secrets

| Secret | Value |
| --- | --- |
| `HETZNER_HOST` | Server IP or hostname |
| `HETZNER_SSH_KEY` | Contents of the private key `dw-deploy` |
| `HETZNER_KNOWN_HOSTS` | Output of `ssh-keyscan -t ed25519 <host>` |

## Cut-over

1. Do the server setup and add the secrets.
2. Copy [`deploy-hetzner.yml`](deploy-hetzner.yml) to `.github/workflows/` and run it once by hand ("Run workflow").
3. Check the site via the server IP: `curl -H "Host: danielwessendorf.com" http://<server-ip>/`.
4. Lower the DNS TTL, then point `danielwessendorf.com` and `www` to the server (A/AAAA). With Cloudflare in front, set SSL mode to "Full (strict)".
5. Enable the `push` trigger in `deploy-hetzner.yml` and remove `pages.yaml` (and `netlify.toml` if Netlify is no longer used).

## Options considered

| Option | Verdict |
| --- | --- |
| **Static files + rsync (this proposal)** | Smallest footprint, no new moving parts, reuses the existing proxy and TLS. |
| App in the `futurelearninglab.de` deploy pipeline | Reuses its detect/deploy workflow, but ties a personal site to the Future Learning Lab repository. |
| Docker image (nginx/Caddy) per deploy | Works, but adds a registry, image builds and a container for files that never change at runtime. |
| Stay on GitHub Pages | Free and zero maintenance, but hosted by a US provider and outside your own infrastructure. |
